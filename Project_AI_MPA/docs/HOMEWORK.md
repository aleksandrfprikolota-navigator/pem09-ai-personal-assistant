# Задание. Личный учебный ассистент

## Этап 1. Роль

Это личный учебный ассистент студента курса по искусственному интеллекту, а не справочник компании и не бот техподдержки. Основной пользователь — сам студент: он возвращается к материалу модуля, проверяет требования к сдаче и задаёт уточнения по ходу диалога. Типичные вопросы: «Какая почта учебной поддержки?», «Что нужно приложить к сдаче?», «Чем RAG отличается от системного промпта?», «Какие роли в учебном Scrum?», «Чем проверить проект перед отправкой?». В базе знаний три текста: путеводитель курса с контактами и командами, конспект по GPT-4o, Whisper, TTS, Vision и RAG, практикум по Python, Scrum и CI/CD. Например, вопрос «Какая почта учебной поддержки?» в режиме `/mode rag` должен опираться на `course_guide.txt` и дать адрес `study@ai-helper.local`. Вне режима RAG бот остаётся собеседником по общей теории и не подменяет эти факты выдуманными контактами.

## Этап 2. База знаний

Файлы лежат в `Project_AI_MPA/data/documents/`:

- `course_guide.txt`
- `ai_study_notes.txt`
- `dev_practice.txt`

Индексация: перезапуск бота или команда `/index`. Статус: `/stats`. Поле «Документов в индексе» должно быть больше нуля. Скриншот `/stats` делается в Telegram после запуска с настоящими ключами.

## Этап 3. Проверки в Telegram

1. `/mode rag`, вопрос по базе, ответ с именем файла-источника.
2. `/mode text`, любой вопрос не из базы, ответ модели.
3. `/mode voice` и голосовое 5–10 секунд: в чате есть распознанный текст и голосовой ответ.
4. Фотография: в чате есть разбор изображения.
5. По желанию: «Нарисуй закат в горах» — в чат приходит картинка.

Ключи в репозиторий не кладутся. Пока в `.env` нет `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY`, эти скриншоты снять нельзя.

## Этап 4. Архитектура

```text
Пользователь → handlers/[text/voice/image/rag] → services/router.py → OpenAI (LLM/Vision/STT/TTS) + ChromaDB (RAG) → ответ в Telegram
```

`handlers` — вход с Telegram: команды, текст, голос, фото и загрузка документов. `services` — клиент OpenAI и маршрутизатор, который выбирает диалог, RAG, разбор фото, распознавание, синтез или генерацию картинки. `rag` загружает файлы из `data`, режет их на фрагменты и ищет ближайшие в ChromaDB. `utils` хранит историю пользователя, логи и конвертацию OGG в WAV. `data` содержит исходные конспекты; векторный индекс создаётся локально и не коммитится.

Маршрут запроса один: обработчик не вызывает модель напрямую, а передаёт сообщение в `services/router.py`. Роутер смотрит режим пользователя и тип запроса, при необходимости достаёт фрагменты из ChromaDB и только потом обращается к нужному методу OpenAI. Готовый текст, голос или изображение возвращается в тот же чат.
